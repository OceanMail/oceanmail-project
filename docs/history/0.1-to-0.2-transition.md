# OceanMail 0.1 → 0.2 Transition

Status: HISTORICAL CONTEXT

OceanMail 0.1 explored a clean-sheet architecture centered on:

```text
OceanMail -> BEMPIC -> M4P -> DataLink
```

That generation produced substantial reusable product/UX ideas, protocol research, queue/security work, and deployment lessons, but its mandatory transport architecture is superseded.

On 2026-09-02/03 the program moved to an upstream-first HERMES/Mercury baseline. BEMPIC was frozen and M4P integration tabled pending comparative evidence or demonstrated field need.

## End-of-generation evidence

This table describes frozen evidence, not current 0.2 implementation state.

| Area | What 0.1 established | What it did not establish |
|---|---|---|
| Desktop/client | A runnable local-first Windows Rust prototype with Mail, Available, transfers, Calendar, Contacts, OChat, Station/Dashboard, Settings, persisted demo state, and transfer-planning behavior. | Its transport was simulated. It did not prove remote synchronization, RF, HERMES, trusted receipts, external delivery, signing, updates, or production security. The current Desktop foundation is Thunderbird, not the prototype shell. |
| Server | Axum/PostgreSQL foundations for health/readiness, durable outgoing queueing, idempotency, leases/recovery, Argon2id authentication, digest-only opaque sessions, device revocation, throttling, audit behavior, and hardened container checks. | It did not complete provider/Mailcow integration, HERMES/Station integration, quotas, billing, abuse controls, or real external delivery. It was never a production-ready mail service. |
| Infrastructure | Provider-neutral Compose/staging models, PostgreSQL backup/restore drills, runtime acceptance, monitoring/rollback material, and supply-chain acceptance gates. | No production or staging service was deployed from the frozen repository, and no approved immutable OceanMail Server release artifact was published through that path. |
| BEMPIC | A detailed Apache-2.0 semantic specification, reference/simulator work, deterministic evidence, and an experimental compact codec candidate. The private compact evidence measured 35-byte warm and 75-byte cold no-change cases; the specification later provisionally allocated experimental tuple `0x00010000/1`. | BEMPIC v0.1.0 was never released, tagged, conformant, or given a stable public wire promise. No qualified reproducible/legal B2F/LZHUF oracle was selected. The public-tuple adoption work was closed without merge when the project froze. |

The BEMPIC measurements are research evidence under their committed fixtures and accounting definitions, not an OceanMail 0.2 performance claim. DCCL was retained only as prior art for compact-codec discipline; OceanMail/BEMPIC did not adopt its wire format, encryption, C++ implementation, or Protobuf dependency.

## Carry-forward rule

Carry forward requirements, behavior, security lessons, test evidence, and rationale only after checking them against current 0.2 boundaries. Do not reintroduce obsolete BEMPIC/M4P assumptions merely because a historical implementation is mature.

In particular:

- port useful Server queue/authentication/container behavior into the active Server deliberately and rerun current tests; do not treat historical commits as already integrated;
- review Infrastructure staging, backup, runtime, and supply-chain controls against the active topology before reintroduction;
- use the old client as UX/domain evidence only where current Desktop decisions have not superseded it;
- do not restart BEMPIC codec/conformance work until the recorded comparative HERMES condition is satisfied; and
- do not revive ordinary sender-selectable transport Priority, the clean-sheet primary navigation shell, or other 0.1 behavior where current 0.2 decisions explicitly supersede it.

Production MFA remains subject to current identity/account contracts and integration validation.

## Repository and licensing disposition

The organization-level repository question is settled by [`OceanMail/oceanmail-project`](https://github.com/OceanMail/oceanmail-project). The active client repository is `OceanMail/oceanmail-desktop`; do not recreate the abandoned `oceanmail` versus `oceanmail-full-client` naming split.

BEMPIC and BEMPIC Reference remain Apache-2.0 research. The permissive license was chosen to support broad implementation and interoperability while providing an explicit patent grant and retaining notice obligations; MIT/BSD-style licensing lacked that patent clarity, while MPL/GPL/AGPL-style copyleft would have narrowed reuse for this protocol/reference role.

All five active 0.2 repositories are public under the installed code/documentation licenses. See [PUBLICATION.md](../../PUBLICATION.md).

## Preservation rule

Historical documents should stay marked historical/frozen/superseded. Their detailed work reports remain the authoritative record of exact commits, test runs, failures/recoveries, and experimental evidence. Current truth belongs in active repositories and this project spine.
