# Security reporting and support

OceanMail 0.2 is experimental. No production security support window or certified
distress/safety capability is claimed. Historical prototypes are unsupported.
Publication does not authorize radio transmission or establish regulatory compliance.

Do not put credentials, private mail, personal data or exploitable vulnerability
details in public issues or PRs. Use GitHub's private **Report a vulnerability**
control in the affected repository's Security tab when it is available. If it is
unavailable, withhold sensitive details and request a private reporting channel
from a maintainer. Do not use a public PR as a substitute.

**Publication gate:** maintainers must enable and test private vulnerability
reporting, or publish and test another private contact route, before inviting
external contributors. That activation has not yet been verified.

A private report should include affected component/commit, impact, minimal
synthetic reproduction, environment and suggested remediation. Avoid testing
against other people's systems or sending real user data. Maintainers coordinate
fixes and disclosure through the private report, preserve provenance and publish
affected/fixed versions when established. No response deadline is promised.
